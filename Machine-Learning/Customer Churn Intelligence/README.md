# Customer Churn Intelligence

An exploratory data analysis and machine-learning project that studies customer churn in a telecommunications dataset and builds a Logistic Regression baseline to identify customers who may leave.

## Project objective

Customer churn is the percentage of customers who stop using a service. The goal of this project is to understand which customer and service characteristics are associated with churn, prepare the data, and evaluate a classification model.

## Dataset

The project uses the Telco Customer Churn CSV stored in `data/WA_Fn-UseC_-Telco-Customer-Churn.csv`.

The dataset contains customer, account, service, billing, and churn information. Examples of analyzed fields include:

- Customer tenure and monthly charges
- Contract type and payment method
- Internet and phone services
- Total charges
- Churn label (`Yes` / `No`)

The `customerID` field is an identifier and is excluded from model features.

## Workflow

1. **Understand the data** — inspect shape, columns, data types, missing values, unique values, duplicates, and churn distribution.
2. **Clean the data** — convert `TotalCharges` to numeric and handle blank values.
3. **Explore churn patterns** — compare churn across contract types, tenure groups, and monthly charges.
4. **Prepare features** — separate the target from input features and use a stratified train/test split.
5. **Preprocess and train** — impute missing values, one-hot encode categorical features, and train Logistic Regression in a Scikit-learn pipeline.
6. **Evaluate** — review accuracy, precision, recall, F1 score, and the confusion matrix.
7. **Save the model** — export the fitted pipeline to `models/churn_logistic_model.pkl`.

## Run locally

Run these commands from this project directory:

```bash
python -m venv .venv
```

Activate the environment:

**Windows**
```bash
.venv\\Scripts\\activate
```

**macOS / Linux**
```bash
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Launch Jupyter:

```bash
jupyter notebook
```

Open `notebooks/01_data_understanding.ipynb` and run the cells from top to bottom. The notebook uses relative paths, so keep the project folder structure unchanged.

## Evaluation

The notebook evaluates the Logistic Regression pipeline on a stratified 80/20 split using:

- Accuracy
- Precision
- Recall
- F1 score
- Confusion matrix

These metrics should be considered together: accuracy alone can hide weak detection of the minority churn class.

## Current scope and limitations

- This repository currently contains a notebook-based analysis and a saved Logistic Regression pipeline; it does not include a deployed web application.
- The saved model is generated by running the notebook. Re-run the notebook if the data or preprocessing workflow changes.
- The analysis identifies patterns and predictive associations. It does not establish that a particular service feature causes churn.
- Model performance should be rechecked on fresh, representative customer data before any business use.
